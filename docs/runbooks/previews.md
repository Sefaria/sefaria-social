# Coolify: the shared dev backend and a preview per pull request

Spec 022. The same pattern as the Library Assistant (`sefaria/ai-chatbot:server` on Coolify): one Coolify app builds
`docker-compose.yaml`. Its main deployment, from `main`, is the shared dev backend that staging and cauldrons use; every
pull request gets a preview with its own copy of all four services, and the reader picks one per page.

## The app

| Setting             | Value                                                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------- |
| Coolify app         | `social` on the Sefaria Dev Server, source: the `coolify-sefaria-github` GitHub App            |
| Build pack          | Docker Compose, `/docker-compose.yaml`, base directory `/`                                     |
| Branch              | `main` (auto-deploy on push)                                                                   |
| Preview deployments | on; preview hosts `{{pr_id}}.{{domain}}`                                                       |
| `app` domain        | `https://app-social.coolifydev.sefaria.org` (port 3200, generated from `SERVICE_URL_APP_3200`) |
| `surface` domain    | `https://surface-social.coolifydev.sefaria.org` (port 8080, `SERVICE_URL_SURFACE_8080`)        |
| `relay` domain      | `https://relay-social.coolifydev.sefaria.org` (port 8787, `SERVICE_URL_RELAY_8787`)            |

These are set in the app's Domains in the Coolify console (Coolify first generated `<service>-<app uuid>` names; renamed to `-social` on 2026-11-25). A
preview for pull request 42 is at `https://42.app-…`, `https://42.surface-…` and `https://42.relay-…`. The Coolify app's uuid is
`glwk1bupcw1mlfrjj8g6pzd2` (project Sefaria, environment production, Sefaria Dev Server).

## Variables (set on the app; every preview gets the same values)

| Variable                                              | Value                                                                                                                                              |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `SOCIAL_JWKS_URL`                                     | the key set of the Django the dev environments sign with, e.g. `https://www.reader-next.cauldron.sefaria.org/.well-known/sefaria-social-jwks.json` |
| `SOCIAL_TOKEN_ISSUER`                                 | that Django's `SOCIAL_TOKEN_ISSUER`                                                                                                                |
| `SOCIAL_ALLOWED_ORIGINS`                              | the reader origins allowed to call the API and open sockets, comma-separated (cauldron hosts with `www.` and without)                              |
| `USER_DELETED_WEBHOOK_SECRET`                         | shared with those Djangos' `USER_DELETED_WEBHOOK_SECRET`                                                                                           |
| `SERVICE_PASSWORD_POSTGRES`, `SERVICE_PASSWORD_RELAY` | generated by Coolify per deployment                                                                                                                |

Never set a variable for one pull request's needs: it changes every preview (the Library Assistant learned this the hard way).
A variable only the pull request's own code reads is harmless to the others.

## Pointing a reader at it

The reader's settings (`nodejs.localsettings` in a cauldron's HelmRelease, read by the `reader` container):

```yaml
PUBLIC_LABS: social # plus whatever else the cauldron already turns on
PUBLIC_SOCIAL_MANIFEST_URL: https://surface-social.coolifydev.sefaria.org/manifest.json
PUBLIC_SOCIAL_ORIGINS: https://surface-social.coolifydev.sefaria.org
PUBLIC_SOCIAL_API_ORIGIN: https://app-social.coolifydev.sefaria.org
PUBLIC_SOCIAL_RELAY_ORIGIN: wss://relay-social.coolifydev.sefaria.org
PUBLIC_SOCIAL_ENVIRONMENT: staging
PUBLIC_SOCIAL_PREVIEWS: "1" # ?social_version=<pr> (reader-next, Sefaria-Project#4129)
```

A page opened with `?social_version=<pr>` (reader-next, outside production) uses that pull request's preview hosts instead.

## Known limits

- The relay runs in workerd under `wrangler dev`: rooms live in memory and in the container's `/tmp`, so a redeploy empties them.
  Production runs the relay on Cloudflare.
- Coolify reads the compose file from the app's branch: a pull request that adds or changes a service shows it in its own
  preview only after it merges (then _Reload Compose_).
- Signed-in use needs the reader's Django to serve `POST /api/social/token` and the key set (Sefaria-Project #4121) with the
  signing key the variables above trust.

## Checked by hand (2026-11-23)

`docker compose -f docker-compose.yaml build` and `up` on a laptop: `app` healthy (`/api/v1/health` 200 with the database
ok), `surface` healthy (`/manifest.json` 200, `Access-Control-Allow-Origin: *`, `Cache-Control: no-cache`), `relay` healthy
(`/health` 200), `postgres` healthy. reader-next pointed at the `surface` container through `PUBLIC_SOCIAL_MANIFEST_URL` loaded
the manifest and every file with integrity checks and mounted the surface.
