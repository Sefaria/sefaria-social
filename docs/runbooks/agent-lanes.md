# Agent lanes, metrics, nightly and retro

How the factory's advisory lanes work and how to operate them (plan 5.5, 5.8, 5.9). Human setup steps are in
[setup-checklist.md](setup-checklist.md); action inputs and deviations from the plan in
[0080-agent-actions.md](../decisions/0080-agent-actions.md).

## Workflows

| Workflow              | Trigger                   | What it does                                                                                               | Needs                                  |
| --------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| `agent-review.yml`    | PR                        | Reviewer agent with `REVIEW.md` from the base; inline comments + a neutral `agent-review` check            | Anthropic key or OIDC ids              |
| `agent-qa.yml`        | PR                        | Surfaces from the diff → planner → runner (browser) → recount → skeptic → one comment                      | Anthropic key or OIDC ids              |
| `security-review.yml` | PR from this repo only    | `claude-code-security-review`; never on forks                                                              | Anthropic API key (no OIDC)            |
| `nightly.yml`         | daily 03:17 UTC, manual   | tests 3× (flake, collection, quarantine), mutation, audit, contract drift, docs freshness, doctor, holdout | holdout: deploy key, repo, staging URL |
| `retro.yml`           | Mondays 06:41 UTC, manual | numbers (no secret) → retro agent                                                                          | agent part: Anthropic key or OIDC ids  |
| `e2e-reader.yml`      | nightly, manual           | L4b against the real reader; **disabled** until the reader seam (A1)                                       | `READER_IMAGE`, `E2E_READER_ENABLED`   |

Every agent job: `timeout-minutes`, `--max-turns`, a minimal `--allowedTools`, `--permission-mode default`, no deploy credentials,
and a `preflight` job (`factory/preflight.mjs`) that skips it with a notice when credentials are absent. `npm run factory --
doctor` checks all of this (`agent-jobs`, `workflows`); `static` also runs actionlint.

## Skips you will see

- `preflight: … skipped: no Anthropic credential is configured …` — expected until the credential exists. The run is green.
- `… the pull request comes from a fork` — agent lanes never run on forks.
- `mutation: No source file … changed in the last day` — nothing to mutate.
- `contract drift: No pinned contract yet` / `The reader has no published contract` — until P1 and A1.
- `e2e-reader disabled` — until A1.

## Metrics

- Every job appends one JSON line to `factory-data` `metrics/YYYY-MM.jsonl` (`factory/metrics.mjs`; schema in that file). ci.yml's
  `metrics` job writes one line per job of the run after `result`; other workflows use `.github/actions/metrics`.
- The branch is created by the first workflow that writes. Never create or edit it by hand. Pushes use the workflow token, which
  triggers no CI.
- A refused push (fork token, a repository that caps the workflow token at read) is a warning, never a failure. If every run warns,
  check the repository's Actions "Workflow permissions" setting (checklist).
- Read locally: `git fetch origin factory-data && git show origin/factory-data:metrics/2026-11.jsonl | head`.

## Flaky tests and quarantine

The nightly runs every suite three times. A test with mixed results fails `tests-3x` until it is fixed or quarantined in
`factory/quarantine.yaml` (reason, issue link, expiry within 30 days). Quarantined tests still run and report; they do not gate.
An expired entry fails the nightly. An agent may add an entry; only a human removes the gate permanently.

## Quality score

`docs/QUALITY_SCORE.md` is generated by `npm run factory -- quality-score`. The nightly's `docs-freshness` fails when it is
stale; regenerate and commit it. The nightly publishes the version with flake counts and escaped defects (issues labelled
`escaped` and `surface:<key>`) to `factory-data` `reports/QUALITY_SCORE.md`.

## Retro

`retro.yml` computes the week's numbers (`npm run factory -- retro`) and publishes `retros/YYYY-Www.md` on `factory-data`; the
retro agent then writes the narrative, opens at most three issues and may propose one smallest edit as a diff in an issue. Try it
locally on the fixture: `npm run factory -- retro --metrics factory/test/fixtures/metrics --retros factory/test/fixtures/retros --week 2026-W48 --fixture`.

## QA promotion

Agent QA is advisory. When the retro lists a surface with 20 consecutive QA runs and no false failure, a human may make agent QA a
required check for it. Record the decision in `docs/decisions/`.
