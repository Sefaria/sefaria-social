## Problem

The social server has no database, no way for a load balancer or an operator to tell whether it is healthy, and no request
logs. Every later server feature (identity, rooms, deletion) needs a Postgres schema that can change without breaking a
rolling deploy, and operators need one log line per request that can be traced from the surface without ever leaking a
token, a header or a request body (plan sections 6.2 and 5.5).

## Acceptance criteria

- AC-001 WHEN the migrations run against an empty database THE SYSTEM SHALL create the tables `rooms`, `room_members`,
  `shiurim`, `shiur_recordings`, `user_display`, `deleted_users` and `webhook_receipts`, with every timestamp column of type
  `timestamp with time zone` and every foreign key covered by an index whose leading columns are the key's columns.
- AC-002 WHEN a migration file drops or renames a table or column, changes a column's type, or sets an existing column NOT
  NULL, and the file has no `-- contract:` line giving the reason, THE SYSTEM SHALL fail the migration check with a message
  naming the file and the statement (expand, deploy, contract).
- AC-003 WHEN anyone calls `GET /api/v1/health` without a token and the database answers THE SYSTEM SHALL respond 200 with
  `{"status":"ok","database":"ok"}`, having called no service other than the database.
- AC-004 WHEN `GET /api/v1/health` is called and the database does not answer within 2 seconds THE SYSTEM SHALL respond 503
  with `{"status":"unavailable","database":"unavailable"}`.
- AC-005 WHEN an API request completes THE SYSTEM SHALL write exactly one JSON log line with a static message, the method,
  the route template, the status, the duration in milliseconds and the correlation id, and SHALL NOT write any request
  header, the request body or the token.
- AC-006 WHEN a request carries an `X-Correlation-Id` of 8 to 64 characters from `[A-Za-z0-9._-]` THE SYSTEM SHALL return
  the same value in the response's `X-Correlation-Id` header and log it; otherwise THE SYSTEM SHALL generate a new id and
  use it in both places.

## Out of scope

- Shipping logs anywhere (Datadog wiring is release work, P5); the server writes JSON lines to stdout.
- Metrics and tracing.
- Any table not listed in AC-001; columns beyond what specs 006–008 need.
- Production database provisioning, backups and credentials (setup checklist).

## Notes for the planner

- Postgres with Drizzle (plan decision D3) and SQL migrations generated by drizzle-kit, committed under
  `app/src/server/db/migrations/` (a protected path, hence `risk: high`).
- Sefaria user ids are plain integers (`bigint`); no shared tables with Django. Store refs and stream pointers, never
  library text.
- Tests use real Postgres: a CI service container, locally Docker or a local Postgres. No mocks of our own database.
- The health check runs `select 1` with a statement timeout; it must not call Django, the JWKS or the relay.
- Log messages are a fixed set of strings checked by the type system; log fields are scalars. A request's headers and body
  never reach the logger.
- The API is TanStack Start server routes under `app/src/routes/api/v1/`, thin handlers calling `app/src/server/services/*`.
